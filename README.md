# Magizh — Maternal & Child Healthcare Companion

Magizh is an educational companion for pregnancy, postnatal recovery and early childcare. It includes stage-aware learning content, an AI assistant that can answer in several Indian languages, voice input and output, reminders, emergency contacts, vital readings and a community feed.

Magizh is an educational tool. It is not a clinical record and does not replace a clinician.

## Features

- Sign up and log in with bcrypt-hashed passwords and JWT sessions
- Consent notice at sign-up, and account deletion from the profile page
- Profile, reminders and emergency contacts synced to the server
- Vital readings (blood pressure, weight, heart rate, temperature) stored per user
- Community posts, likes, comments, with delete for your own content
- Magizh AI assistant (Ollama, local or Ollama Cloud), answering in the language chosen in the app
- Voice mode with ElevenLabs speech-to-text and text-to-speech
- SQLite for local development, PostgreSQL for production
- Rate limits on sign-in, sign-up, AI chat and voice requests

Supported interface languages: English, Tamil, Hindi, Telugu, Kannada, Malayalam. The language setting also controls the language of AI answers and voice recognition. Most buttons and headings are still in English; see "Known limitations".

## Project layout

```

src/main.jsx        React frontend (single-page app)

```

## 1. Local development

Requirements: Node.js 20 or newer, and Ollama if you want AI answers.

```cmd
npm install
copy .env.example .env
```

Edit `.env` and set at least `JWT_SECRET`. The defaults in `.env.example` use a local Ollama server.

Start Ollama with a model:

```cmd
ollama run qwen3:8b
```

Start the app:

```cmd
npm run dev
```

Open `http://localhost:5173`. The Vite dev server proxies `/api` to the backend on port 8787.

## 2. Environment variables

| Variable | Required | Notes |
| --- | --- | --- |
| `NODE_ENV` | Production | Set to `production` on the server. |
| `PORT` | No | Defaults to 8787. Render sets this for you. |
| `JWT_SECRET` | Yes in production | At least 32 random characters. The server refuses to start in production otherwise. |
| `DATABASE_URL` | Production | PostgreSQL connection string. Leave empty for SQLite. |
| `DATABASE_SSL` | No | Set to `false` only if your PostgreSQL provider does not use SSL. |
| `DB_PATH` | No | SQLite file path for development. |
| `FRONTEND_ORIGIN` | If frontend is on another domain | Exact origin of the frontend, for example `https://magizh.vercel.app`. |
| `OLLAMA_BASE_URL` | Yes | `http://127.0.0.1:11434` locally, `https://ollama.com` in production. |
| `OLLAMA_MODEL` | Yes | Model name, for example `qwen3:8b` locally or `gpt-oss:20b-cloud` in production. |
| `OLLAMA_API_KEY` | Production | Ollama Cloud key. Server-side only. |
| `ELEVENLABS_API_KEY` | For voice | Server-side only. |
| `ELEVENLABS_VOICE_ID` | For voice | Voice used for spoken answers. |
| `VITE_API_BASE_URL` | Frontend build | Backend URL, used only when the frontend is hosted separately. Public value. |

Never put `OLLAMA_API_KEY` or `ELEVENLABS_API_KEY` in a `VITE_` variable. Those are exposed to the browser.

## 3. Production deployment (Vercel frontend + Render backend)

### Backend on Render

1. Create a PostgreSQL database on Render and copy its internal or external connection string.
2. Create a Render Web Service from this repository.
3. Build command: `npm install && npm run build`
4. Start command: `npm start`
5. Health check path: `/api/health`
6. Environment variables: `NODE_ENV=production`, `JWT_SECRET`, `DATABASE_URL`, `FRONTEND_ORIGIN` (your Vercel URL, set after step 2 of the frontend), `OLLAMA_BASE_URL`, `OLLAMA_MODEL`, `OLLAMA_API_KEY`, `ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID`.

Note the backend URL, for example `https://magizh-backend.onrender.com`.

### Frontend on Vercel

1. Import the repository in Vercel.
2. Framework preset: Vite. Build command: `npm run build`. Output directory: `dist`.
3. Environment variable: `VITE_API_BASE_URL=https://magizh-backend.onrender.com` (the Render URL, no trailing slash).
4. Deploy, then copy the Vercel URL into `FRONTEND_ORIGIN` on Render and redeploy the backend.

The backend also serves the built frontend from `dist/`, so the whole app can run as one Render service if you prefer. In that case `VITE_API_BASE_URL` and `FRONTEND_ORIGIN` can be left empty.

## 4. API

All endpoints except `/api/health`, `/api/auth/signup` and `/api/auth/login` require `Authorization: Bearer <token>`.

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/api/health` | Status and which integrations are configured |
| POST | `/api/auth/signup` | Create account (requires `consent: true`) |
| POST | `/api/auth/login` | Log in |
| GET | `/api/auth/me` | Current user and profile |
| DELETE | `/api/auth/account` | Permanently delete the account (requires `password`) |
| GET / PUT | `/api/profile` | Profile |
| GET / PUT | `/api/reminders` | Reminders (replaces the list) |
| GET / PUT | `/api/contacts` | Emergency contacts (replaces the list) |
| GET / POST | `/api/vitals` | List or add vital readings |
| DELETE | `/api/vitals/:id` | Delete one of your readings |
| GET / POST | `/api/community/posts` | List or create posts |
| POST | `/api/community/posts/:id/like` | Toggle your like |
| POST | `/api/community/posts/:id/comments` | Add a comment |
| DELETE | `/api/community/posts/:id` | Delete your post |
| DELETE | `/api/community/comments/:id` | Delete your comment |
| POST | `/api/chat` | Ask Magizh AI (`question`, `history`, `profile`, `language`) |
| POST | `/api/voice/transcribe` | Speech to text (multipart: `audio`, optional `language`) |
| POST | `/api/voice/speak` | Text to speech (`text`), returns MP3 |

## 5. Privacy and data

- Health-related information the user enters (profile, reminders, vital readings, chat questions) is stored on the backend database.
- Chat questions are sent to the AI provider set in `OLLAMA_BASE_URL`. Voice input and spoken answers are sent to ElevenLabs.
- Users accept this at sign-up, and the notice is shown on the profile page. Users can delete their account and all of its data from the profile page.
- Before public launch, the privacy notice should be reviewed by legal counsel for the regions you serve.

## 6. Security notes

- Passwords are hashed with bcrypt (cost 12).
- Sign-in and sign-up are rate limited per IP. AI and voice requests are rate limited per user. Limits are kept in memory per server instance.
- Static files are served only from `dist/`. Requests that try to leave that folder are answered with the app shell.
- Error responses to users are generic. Details are written to the server log.

## Known limitations

- Most interface text (buttons, headings, learning content) is English. Only the navigation labels are translated. Translations of the full interface need review by native speakers before they are added.
- The Learn section content is English only.
- Login tokens are stored in the browser's local storage. Acceptable for this stage; an HTTP-only cookie session is the next hardening step if the app grows.
- Rate limits are per instance. If you run several backend instances, move them to a shared store such as Redis.

## Database note

SQLite is for local development. Production must use managed PostgreSQL, because Render's filesystem is not persistent unless you attach a disk.
